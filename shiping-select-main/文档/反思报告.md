# 视频学习资源智能筛选系统反思报告

> 本报告为初稿框架，完整运行、人工对照评估和 Prompt 调优完成后再补足到 1500 字以上。

## 一、项目完成情况

本项目围绕“视频学习资源智能筛选系统”展开，目标是输入学习主题后，自动从视频平台检索候选资源，抓取元数据与字幕，并调用大语言模型进行教学价值评估，最终输出 CSV 表格和 Markdown 推荐清单。

目前项目已经完成 B 站搜索、YouTube 搜索、字幕抓取逻辑、统一数据模型、LLM 评估模块、结果导出模块和基础测试。已验证 B 站最小流程可以运行，并能生成 CSV、JSON、Markdown 和运行日志；也已验证 YouTube 单平台完整流程可以通过代理运行，并成功调用大模型完成 15 条视频评估。

## 二、当前遇到的主要问题

### 1. B 站公开视频字幕覆盖率不稳定

在使用“PCA 主成分分析”作为主题测试 B 站搜索时，系统成功返回 15 条视频，但字幕成功数为 0。初步检查发现，接口返回的字幕列表为空，说明问题不一定是程序崩溃，而是这些视频本身未提供公开字幕，或匿名接口无法获取相关字幕。

这个问题提醒我们，项目书中的“字幕获取成功率 ≥ 80%”在真实平台环境中存在不确定性。后续需要通过 YouTube transcript、ASR 兜底或无字幕降级评估来提高系统鲁棒性。

### 2. API Key 与复现环境需要提前准备

完整流程依赖 `YOUTUBE_API_KEY` 和 `OPENAI_API_KEY`。配置 `.env` 后，YouTube 搜索和 LLM 评估可以正常运行。首次运行时，YouTube 搜索模块使用 `google-api-python-client` 出现代理超时；后续改为 `httpx` 直接调用 YouTube REST API 后，搜索链路稳定跑通。

### 3. YouTube transcript 抓取受到网络出口限制

项目中使用的 `youtube-transcript-api` 已更新接口，旧写法 `YouTubeTranscriptApi.list_transcripts(...)` 不再可用。代码已兼容新版 `YouTubeTranscriptApi().fetch(...)` 接口。但在当前网络出口下，访问 YouTube transcript 页面会触发 `IpBlocked`，导致字幕抓取仍然失败。这个问题与 YouTube Data API Key 不同，不是搜索接口失败，而是字幕网页抓取被限制。

### 4. 抖音抓取工程代价较高

新增的抖音爬虫原型依赖 DrissionPage、Chrome 浏览器和登录态，需要扫码登录并监听浏览器数据包。它能作为选做模块的参考，但不适合直接并入主线。相比 B 站和 YouTube，抖音更接近封闭平台，维护成本和不稳定性明显更高。

## 三、后续改进计划

1. 抽取 10 条视频进行人工对照评估，计算系统推荐与人工判断的一致率。
2. 根据误判案例迭代 Prompt，至少记录 3 个版本。
3. 优化 Markdown 输出，使其更接近“入门 / 进阶 / 实操 / 应用”的分层推荐清单。
4. 针对字幕问题，尝试更换网络出口、降低请求频率，或后续接入 ASR 兜底。
5. 若时间允许，再考虑抖音抓取选做模块。

## 五、真实问题记录

| 问题 | 表现 | 解决或处理方式 |
| --- | --- | --- |
| Python 版本与 PATH | 终端默认 Python 版本不符合预期 | 调整默认 Python 到 3.14，并使用 `.venv` |

| B 站字幕为 0 | PCA 主题 15 条结果均无字幕 | 记录为平台字幕覆盖风险，后续用 YouTube / ASR / 降级评估补足 |

| YouTube 搜索超时 | `google-api-python-client` 在代理环境下连接失败 | 改用 `httpx` REST API 调用 YouTube Data API |
| YouTube 字幕失败 | 新版接口变化且当前出口触发 `IpBlocked` | 已兼容新版接口；后续尝试更换出口或 ASR |
