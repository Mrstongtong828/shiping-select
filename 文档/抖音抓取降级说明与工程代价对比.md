# 抖音抓取降级说明与工程代价对比

## 背景

抖音网页端内容检索依赖登录态、浏览器指纹、风控策略和页面接口变化。与 B 站公开视频页面、YouTube Data API 相比，抖音缺少稳定公开检索 API，直接在主流程中做自动网页登录抓取容易出现验证码、接口变更、Cookie 失效、账号风控和复现实验困难等问题。

因此当前项目采用“参考爬虫导出 JSON + 主流程统一接入”的降级方案：抖音侧由 `douyinpachong-main/` 或人工登录后的参考脚本生成 JSON，主项目通过 `src/search_douyin.py` 读取该 JSON，并转换为统一 `VideoRecord`，再复用 CSV、JSON、Markdown、日志和可选 LLM 评估链路。

## 可运行降级方案

默认情况下，主流程会尝试读取仓库内参考样例：

```powershell
python main.py --topic "PCA 主成分分析" --platform douyin --max 10 --skip-evaluate
```

如果使用新的抖音参考导出文件，可以通过环境变量指定：

```powershell
$env:DOUYIN_SAMPLE_JSON="C:\path\to\douyin_export.json"
python main.py --topic "PCA 主成分分析" --platform douyin --max 10 --skip-evaluate
```

也可以与其他平台组合运行：

```powershell
python main.py --topic "PCA 主成分分析" --platform bilibili,youtube,douyin --max 30
```

降级输入 JSON 至少应包含标题、链接、作者、播放数或点赞数中可获得的字段。主项目会尽量兼容中文字段名和常见导出字段，并统一映射为 `platform="douyin"` 的 `VideoRecord`。

## 工程代价对比

| 方案 | 实现代价 | 稳定性 | 可复现性 | 风险 |
| --- | --- | --- | --- | --- |
| 直接自动网页登录抓取 | 高，需要维护登录态、Cookie、请求签名、浏览器指纹和验证码处理 | 低，页面结构和接口参数可能频繁变化 | 低，不同账号和网络环境结果差异大 | 容易触发风控，不适合高频或无人值守运行 |
| 人工登录后运行参考爬虫导出 JSON | 中，需要人工完成登录和导出步骤 | 中，登录态有效期内可用 | 中，导出的 JSON 可归档复验 | 仍受账号、页面和接口变化影响 |
| 当前主流程读取参考 JSON | 低，主项目只负责结构化接入和统一导出 | 高，只要 JSON 文件存在即可复跑 | 高，适合答辩和工程验收 | 不能证明实时抖音搜索能力，只能证明整合能力 |

## 验收边界

当前实现满足加分项中的工程整合部分：CLI 支持 `--platform douyin`，抖音模块返回标题、URL、作者、播放/点赞可得字段，并进入统一 VideoRecord 和统一导出链路。若正式答辩需要展示抖音实时抓取，应先人工登录浏览器，使用参考爬虫生成新的 JSON，再通过 `DOUYIN_SAMPLE_JSON` 接入主流程。

该边界不会替代 B 站 + YouTube 的终验主链路。完整终验仍应以：

```powershell
python main.py --topic "PCA 主成分分析" --platform bilibili,youtube --max 30
```

作为硬性验收命令；抖音只作为加分整合和工程代价分析展示。
